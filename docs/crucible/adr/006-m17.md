# 006. M17 voice: a new air mode on core/air, Codec 2 from codec2-fixed-point

| | |
|---|---|
| Status | Accepted |
| Date | 2026-11-27 |
| Decides | How Crucible receives and sends M17 voice: where the code lives, which codec, where its memory comes from, which outside code it learns from, and in what order the work lands |

## Context

M17 is an open digital voice mode: 4FSK at 4800 symbols/s, 9 kHz wide, 12.5 kHz channels, voice in Codec 2 at
3200 bit/s. The specification is the M17 Project's (v2.1.1, 2026-11-19; GFDL-1.3 text, its code GPL-2.0-or-later).
The owner's roadmap ([ADR 005](005-ysf-vw-vd1.md)) puts it after YSF VW and V/D mode 1 and before NXDN. RadioFoundry
has no M17 code: on `upstream/main` (5168a55d) the word appears only in passing (the hotspot's list of MMDVM modes it
refuses, a radio's model name, a USB audio note, qdmr test data).

### What the tree already has

M17 shares its physical layer with modes the tree already runs. ADR 005 adds the rest of the frame on our side.

| Need | Where it is | For M17 |
|---|---|---|
| Symbols, profiles, fit (`hal_air.h`) | `core/air`, each provider | M17's dibit map (01 +3, 00 +1, 10 -1, 11 -3) is the tree's. RRC pulse with a roll-off, outer deviation, sync patterns of 8 to 24 symbols: all expressible |
| Receive through the soft modem | `air_softmodem.c` | Its syncs are 8 symbols, so no chip correlator takes them (24 symbols, `hal_air.h`). Receive runs on the soft modem, as YSF's does today |
| Framer, session, `air_voice` | `core/air` | Unchanged. M17 is the third user after NXDN and YSF |
| Transmit | Each chip's 4FSK modulator | Both chips send their DMR pulse (RRC 0.2): `AIR_FIT_SHAPE_APPROX`, as for YSF. The soft modem has no transmit half |
| K=5, rate 1/2 convolutional code, soft Viterbi | `core/fec/conv.{c,h}` (NXDN's) | M17's polynomials (G1 = 1+D^3+D^4, G2 = 1+D+D^2+D^4) are a mask pair. A punctured bit is a soft 0, which the decoder already takes |
| Golay (24,12) | `core/fec/golay.{c,h}` | The same code family. Bit layout to be checked against the spec's matrix in step 1; a wrapper if it differs |
| Voice through a software codec, memory lent by an idle mode | `p25Voice` (IMBE), ADR 005's VW path | The model for M17's Codec 2 path: queues, priming, concealment, levels |

What is new:

| Part | Size of the job |
|---|---|
| Frame codec: LSF, LICH (6 chunks of 40 bits, LICH_CNT), stream frame (FN + 128 bits), packet frame (receive only, decoded and dropped) | New, `core/m17` |
| CRC-16 poly 0x5935, init 0xFFFF; puncture patterns P1 (61/46, LSF), P2 (12/11, stream), P3 (8/7, packet); QPP interleaver over 368 bits; the 46-byte randomizer | New, small; vectors in the spec |
| Callsign base-40 (9 characters, 48 bits), BROADCAST (all ones), the reserved and extended ranges | New, small |
| CAN (channel access number, 4 bits in TYPE) | A squelch, as YSF's DG-ID |
| Preamble (+3/-3, 40 ms), EoT (0x555D repeated, 40 ms), FN end bit | Transmit cycle and call end |
| Signed streams (v2.1.0): an authentication frame (FN 0x7FFB) and 4 signature frames after the voice | Must not reach the codec. Verification needs ECDSA P-256: not covered |
| Codec 2 3200 | New: codec2-fixed-point (below) |

### The codec

codec2-fixed-point 0.1.0 (`~/src/codec2-fixed-point`, the owner's, `github.com/dbehnke/codec2-fixed-point`, public):
an integer-only Codec 2 3200 encoder and decoder, standard bitstream (8 bytes per 20 ms frame of 160 samples at
8 kHz). Built from the M17 Project's Codec2-mod and David Rowe's Codec 2.

### The CPU

The STM32F4 radios run at **72 MHz** (HSE 8 MHz / 4 x 72 / 2; `system_uvf.c`, `hardware-md9600.md`), as the stock
firmware does. A 20 ms frame is 1.44 M cycles there. The HR_C7000 radios run at 168 MHz: 3.36 M cycles.

If the Thumb-2 build needs about as many instructions as the CK803S one, and each costs 1.2 to 1.5 cycles from flash
with three wait states, the decoder takes 0.53 to 0.66 M cycles per frame on the STM32F4 radios: 37 to 46 % of the CPU
while a call plays, with the soft modem running too. On the CK803S at 168 MHz it is under 20 %. Both are estimates from
an emulator's instruction count on another instruction set. Step 1 measures them on the radios.

## Decision

### 1. M17 is its own air mode on core/air

M17 gets its own channel kind, engine and radio core glue, next to NXDN and YSF, in `core/m17` and
`core/radio/radio_m17.c`. It uses `air_voice`, the framer, the session and the soft modem unchanged. It is not a
third voice path inside YSF: its frames, addresses and codec share nothing with YSF's.

| File | What |
|---|---|
| `core/m17/m17_frame.{c,h}` | LSF, LICH, stream and packet frames: CRC, Golay, convolutional code with puncturing (on `core/fec/conv`), interleaver, randomizer. Bytes and soft values in, fields out |
| `core/m17/m17_addr.{c,h}` | Base-40 callsigns, BROADCAST, the reserved and extended ranges shown as hex |
| `core/m17/m17_call.c` | Call layer: LSF or LICH late entry, CAN squelch, FN and the end bit, EoT, signed-stream frames held back, transmit cycle |
| `core/m17/m17_engine.{c,h}` | The engine on `air_voice`, its `air_profile_t`, fit |
| `core/m17/m17_voice.{c,h}` | Codec 2 between the engine and `hal_audio_t`, on `p25Voice`'s design |
| `core/m17/m17_codeplug.{c,h}` | The channel block and the radio-wide record (6) |
| `core/radio/radio_m17.{c,h}` | Radio core glue, as `radio_ysf.c`; `RADIO_MODE_M17` wherever `radio_sm.c` names YSF |
| `core/debuglink/debuglink_view_m17.c` | The `m17` view (7) |

Every new file is headed `GPL-3.0-or-later` with David Behnke's line (AGENTS.md rule 3).

### 2. The profile

| Field | Value |
|---|---|
| `sym_rate`, `levels` | 4800, 4 |
| `shape`, `shape_param` | `AIR_SHAPE_RRC`, 50 |
| `dev_outer_hz` | 2400 (inner 800) |
| `timing`, `bw` | Continuous, 12.5 kHz |
| Syncs | Stream 0xFF5D, packet 0x75FF, LSF 0x55F7 (8 symbols each, `max_errs` 0 or 1, set in step 2 from the false-sync rate on noise). A 24-symbol START_ONLY pattern: 16 preamble symbols and the LSF sync. BERT 0xDF55 not listed |
| `sync_every_syms`, `sync_any_syms` | 0 (no recurring 24-symbol pattern), 192 (one frame) |
| `rx_opts` | 0 in step 2. The equalizer is tried on captured repeater signals; added if it helps, as YSF did |
| `idle` | Preamble dibits |

| Provider | Fit |
|---|---|
| HR_C6000 (STM32F4 radios) | Receive through the soft modem on the tap (no 24-symbol recurring sync). Transmit at 2400 Hz, inside its 1050-2400 Hz range, `SHAPE_APPROX` |
| HR_C7000 | Receive through the soft modem. Transmit inside its 100-6000 Hz window, `SHAPE_APPROX` |

The RRC 0.2 pulse is narrower in time than the spec's RRC 0.5. An M17 receiver's matched filter then sees some
inter-symbol interference. YSF transmits the same way today. Step 2 checks our soft modem on both pulses. Step 5
checks other receivers on air. If they fail, a transmit half for the soft modem gets its own record.

behaviors, two sets of vectors and two memory plans, and upstream's library allocates on the heap.

### 4. Memory

A radio transmits or receives, so the encoder and the decoder share one block: a union, 4,504 B. Both are set up again
at the start of each call or transmission.

`m17_voice_mem_t` = that union, a receive queue of Codec 2 frames (8 B each, a few stream frames' worth for priming
and jitter) and a transmit queue. Estimate: 4,800 B. `m17_engine_t` = `air_voice_t`, a frame buffer (48 B) with its
soft values (192 B), the depunctured soft bits and Viterbi decisions of one LSF (488 B each), the LSF being
assembled from LICH chunks, the call, the transmit state. Estimate: 1,600 B, or 3,200 B with the adapt state.

| Platform | Engine | Voice memory | RAM added |
|---|---|---|---|
| STM32F4 (no lend), P25 on | ADR 005's CCM engine block becomes a union of `ysf_engine_t` and `m17_engine_t`. It is built when `CONFIG_YSF_VW` or `CONFIG_M17` is on | P25's idle block: 5,576 B for about 4,800 B | None with VW on, while `m17_engine_t` is at most 4,208 B. With VW off: a static CCM block of `m17_engine_t` alone, 1.6 to 3.2 KB out of the CCM heap's 8,328 B margin on main |
| HR_C7000 (lends) | The shared engine union (`radio_air_mem.c`) gains `m17_engine_t` | The vocoder's lend (7,168 B), as VW's IMBE path borrows it. The AMBE+2 state is rebuilt on the next DMR call | None while `m17_engine_t` is at most `ysf_engine_t` |
| Either, P25 off (a CI build) | The shared union | A static block of its own | About 4.8 KB of main RAM, plus any engine growth |

Static asserts tie each size to its block. `radio_air_mem.c` keeps the platform test it has (`HAL_VOCODER_LEND_BYTES`),
so `core/` still names no platform.

**Stack.** Codec 2 runs in the audio callback, where `p25Voice` runs IMBE. The audio task's stack is sized for the
software vocoder (5,120 B on the STM32F4 radios, 6,144 B on the HR_C7000 radios; about 4 KB used). Codec 2 needs at
most 1,444 B, and the two never run at once. `make stack-check` confirms it in step 1.

**Flash.** Codec 2 (26.3 KB on Cortex-M4) plus a mode (12 to 22 KB, above): 38 to 48 KB.

| Radio | Free with VW receive | Left after M17 |
|---|---|---|
| dm1701 | 107,860 | 60 to 70 KB |
| md9600 | 128,764 | 81 to 91 KB |
| mduv380 | 106,608 | 59 to 69 KB |
| dm32, db25d | 203,616 and 233,076 (main) | Over 150 KB |

VW transmit (ADR 005 step 4) takes some of that first. No feature needs to go: the freed HOTSPOT, SFR and ZONE_SHARE
flash covers it.

### 5. The CPU gate

Step 1 adds a debug link benchmark: encode and decode a fixed frame set, cycles per frame from the CPU's counter
(DWT on Cortex-M4, the core timer on the CK803S). The owner runs it on each radio. Step 2 adds the receive path's load
(soft modem, framer, codec) from the same counters during a played call.

| Result per radio | Then |
|---|---|
| Receive path at most 60 % of the CPU, encode at most 50 % | M17 on |
| Above | In order: the codec under `-O2`; its hot loops in SRAM (no wait states; CCM cannot run code); a faster clock while M17 runs, in its own record (the clock already changes at run time for eco mode). Else `CONFIG_M17` off for that platform in `config/crucible.mk`, and the feature matrix says so |

### 6. Codeplug and site

Kind **7** (0x07) in the three registries (`channel-modes.md` 4, `codeplug_modes.h`, `modes.js`), with its spec
`docs/spec/m17-codeplug.md`. The owner's choice (2026-11-27): the DM32 fork's web CPS (Open25-DM32,
`donttellmeimcute/dm32-web-cps-flasher`, GPL-3.0-or-later) already ships M17 as kind 7, and the dm32 is one of our
radios. With the same kind and block, M17 channels in that fork's codeplugs read correctly in ours. Its other kinds
(5 AM, 6 YSF, 8 NXDN scrambler, 9 D-STAR) don't match ours (5 DMR AES, 103 YSF); only M17 is made compatible.

The cost: RadioFoundry appends its kinds and may assign 7 one day. Each upstream sync checks upstream's
`codeplug_modes.h`; a clash means a renumber or a conflict resolved by hand, and codeplugs already written keep their
kind 7.

Channel parameter block:

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | Bits 0-3: CAN, 0-15. Bit 4: hear every CAN (1) or this CAN only (0), Crucible's own: the fork's editor keeps bits 4-7 as read and writes 0. Bits 5-7: reserved, kept, written 0 |
| 1 | 9 | Destination: 9 characters of printable ASCII from A-Z, 0-9, `-`, `/`, `.` and space, upper case, space padded, as the fork stores it (text, not the base-40 address). Blank, absent or "ALL": BROADCAST. Encoded to base-40 when a transmission starts |

A zeroed or absent block sends CAN 0 to BROADCAST and hears CAN 0, as the fork reads it (`can: 0, dest: "ALL"`). The destination lives in the block, not in a target
record (`channel-modes.md` 5.2): a channel calls one reflector module or station. A target list can come later if
users ask for a picker.

Radio-wide record, key 0x0A07: the source callsign, 9 bytes in the destination's encoding, as the fork's record.
Step 3 confirms the fork's record key against ours. Empty or absent: the YSF record's callsign (read from the codeplug, so it works with `CONFIG_YSF` off), else the
radio name's (`ysf_callsign_from_name`, moved to a shared place both modes call). One callsign set once serves both
modes.

Base record: name, frequencies, power, time-out, scan skip as any channel. The stand-in shape is DMR receive only, as
YSF's.

**Codeplug Editor.** `mode_m17.js`: CAN, "Hear every CAN", Destination (text; blank means ALL). Settings: the M17
callsign. `newParams` `{ can: 0, dest: "ALL" }`, transmit by default, its own frequencies, no system, no contacts, as
the fork's module. `encode` keeps unknown bytes. Written from the fork's layout; if its code is taken, the file keeps
its notice (Copyright (c) 2026 lyra XE1POC, GPL-3.0-or-later) and CREDITS.md credits it in the same commit.
`site/tests/modes.test.mjs` gets vectors, among them a block made by the fork's editor. The simulated radios
(`site/tests/simradios.test.mjs`, `everyRadio()`) round-trip an M17 channel, and `cpsSim --detail` prints the block as it
does for YSF.

**CSV.** The Mode column names kinds from `modes.js` `KINDS`, so "M17" imports and exports once kind 7 is there. New
columns, as YSF's in `csv.js`: "M17 CAN", "M17 Destination", "M17 Hear Every CAN". If qdmr's codeplug has M17 channel fields,
`qdmr.js` maps them in step 3.

### 8. Levels

M17 gets its own `tx_level_m17` and `rx_agc_m17`, as YSF has ([ADR 003](003-digital-agc.md)), appended to the
settings record in step 4. `m17_voice` takes them when the path starts. Step 4 measures transmit level against ADR
003's on-air target.

### 9. Switch

`CONFIG_M17` in `config/features.mk` (`?= n`, as a mode stays off until it runs, `adding-a-mode.md`) and
`core/config.h`. It turns on `CONFIG_AIR` (added to the derived list) and joins `CONFIG_AIR_RX_ADAPT`'s condition.
It needs no `CONFIG_DMR`: its voice is its own. `config/crucible.mk` sets `CONFIG_M17 ?= y` in step 2, once receive
works. `crucible.toml [ci] matrix` gets "M17". The maximal build carries it from step 1, so its code compiles in CI
before it is on by default. A radio that fails step 1's gate gets it off in `config/crucible.mk`, keyed on the
platform (the three STM32F4 radios share one MCU and clock), never in a board's own `config.mk`, which stays
upstream's (CRUCIBLE.md rule 4). M17 needs no board work: the providers carry the profile (2).

## Options considered

| Option | Why not |
|---|---|
| Float Codec 2 (upstream or Codec2-mod) on the STM32F4 radios, codec2-fixed-point on C-SKY | Two codecs, two sets of vectors, two memory plans. Upstream allocates on the heap. The fixed-point codec matches upstream's quality (PESQ-NB 2.676 against 2.677) |
| Port OpenRTX's M17 stack | C++, with its own demodulator and runtime. We have the soft modem, framer and FEC in C. A second demodulator breaks "one stack" |
| Take libm17 whole | Its float demodulator, Viterbi and Golay duplicate `core/air` and `core/fec`. Pieces that map one to one may come in (11) |
| M17 as a third voice path inside the YSF engine | M17 shares no frame, address or codec with YSF. Only `air_voice` and the memory blocks are common, and those are shared already |
| Encoder and decoder state side by side (7,564 B) | Does not fit P25's idle block (5,576 B) on the STM32F4 radios. A radio never encodes and decodes at once |
| M17's engine in P25's idle block beside the codec | 1.6 to 3.2 KB plus 4.8 KB: more than 5,576 B |
| Kind 104, after YSF's 103, with a 6-byte base-40 destination | Never collides with upstream's appended kinds, but dm32 codeplugs from the DM32 fork would not read. The owner chose compatibility (6) |
| A target record for the destination now | One destination per channel covers repeaters and reflector modules. Targets need zone sharing's target part first (`channel-modes.md` 5.2) |
| A transmit half for the soft modem (RRC 0.5 exactly) | Not written for any mode. YSF works with the chip's pulse. Taken up only if step 5 shows receivers failing |
| A faster STM32F4 clock now | Touches every timer, PWM and baud rate on three radios. Only if step 1's gate fails, in its own record |
| Cut USB_NETWORK or SATELLITE_TLE for flash | Not needed: 59 KB or more stays free on every STM32F4 radio. The owner decides any such cut |
| Wait for RadioFoundry | No M17 work upstream. Crucible sends nothing upstream |

## Consequences

- **Flash.** 38 to 48 KB on each STM32F4 radio, 59 KB or more left. More room on the HR_C7000 radios.
- **RAM.** None on the HR_C7000 radios. None on the STM32F4 radios with VW on, if `m17_engine_t` stays within
  `ysf_engine_t`; else the difference from the CCM heap, whose margin is 4,096 B. Step 1 confirms both from the map,
  and the heap high-water mark on each STM32F4 radio.
- **CPU.** The open risk. At 72 MHz the decoder alone may take 37 to 46 % of the CPU on the STM32F4 radios. Step 1's
  gate decides per radio. The HR_C7000 radios have room.
- **Switching cost.** On the HR_C7000 radios, a DMR call after an M17 call rebuilds the AMBE+2 state from the lend, as
  after a VW call. Scan and dual watch across DMR and M17 channels pay it at each change.
- **Upstream merges.** `features.mk`, `config.h`, `radio_sm.c`, `radio_air_mem.c`, `codeplug_modes.h`, `modes.js`,
  `settings.h`, `debuglink.c` change. `radio_sm.c` is large and RadioFoundry changes it often: each M17 hook there is
  one line beside its YSF twin, to keep conflicts small.
- **Licenses.** A first LGPL component, and possibly GPL-2.0-or-later files from libm17. Both are GPL-3.0 compatible.
  Their notices and texts ship with every release.
- **Versions.** Step 2 merges a feature: the minor rises in that commit if the queued version was released by then
  (CRUCIBLE.md, Versions).
- **On air.** The chip pulse (RRC 0.2) against the spec's RRC 0.5 is unproven with other receivers until step 5.
- **Not covered.** Packet mode (SMS, APRS over M17), BERT, sending or verifying signed streams, encryption, Codec 2
  1600, sending META data, M17 over IP (a reflector client on the USB network), the hotspot's M17 mode. Each can get a
  record of its own.
