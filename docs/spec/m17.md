# M17

M17 voice (the M17 specification 2.x, [spec.m17project.org](https://spec.m17project.org)), on the air interface
([air-interface.md](air-interface.md)). Switch: `CONFIG_M17`, off by default; it also builds the air interface
([build-config.md](../build-config.md)). Which radios could carry it: [feature-matrix.md](../feature-matrix.md). The
design and the order of the work: [ADR 006](../crucible/adr/006-m17.md). "Spec" columns name the specification's
sections; a letter is an appendix.

State:

| Part | State |
|---|---|
| Frames: LSF, LICH, stream frame, CRC, coding (2) | written, host tested against libm17's frames bit for bit |
| Addresses (3) | written, host tested against the specification's example and libm17 |
| Voice: Codec 2 3200 queues (4) | written, host tested on the synthesized test speech; not connected to the radio's audio |
| The CPU benchmark (5) | written; the debug link runs it ([debuglink.md](debuglink.md) 3.8). Not yet run on a radio |
| Receive, the call layer, the engine, the radio core, codeplug channels, transmit | not written (ADR 006, steps 2 to 4) |
| Packet frames, BERT, encryption, signed streams' verification | not written: voice only |

## 1. On air

| Item | Value | Spec |
|---|---|---|
| Modulation | 4FSK, 4800 symbols/s, RRC pulse (alpha 0.5) | Physical Layer |
| Deviation | +3: +2400 Hz, +1: +800 Hz, -1: -800 Hz, -3: -2400 Hz | Physical Layer |
| Symbol to dibit | +3 = 01, +1 = 00, -1 = 10, -3 = 11, the air interface's map | Physical Layer |
| Frame | 192 symbols (40 ms): an 8-symbol sync and 368 payload bits | Data Link Layer: Frame |
| Bit order | MSB first, two bits to a symbol | Data Link Layer: Frame |
| Channel | 12.5 kHz, continuous | Physical Layer |

A transmission:

| Part | Length | Content |
|---|---|---|
| Preamble | 192 symbols | +3, -3 alternating before an LSF |
| LSF | 1 frame | sync 0x55F7, the link setup frame (2.2) |
| Stream frames | 1 per 40 ms | sync 0xFF5D, a sixth of the LSF (LICH), the frame number and 16 bytes of voice |
| EoT | 192 symbols | 0x555D repeated |

| Sync | Word | Frame |
|---|---|---|
| `M17_SYNC_LSF` | 0x55F7 | link setup |
| `M17_SYNC_STREAM` | 0xFF5D | stream |
| `M17_SYNC_PACKET` | 0x75FF | packet (not decoded) |
| `M17_SYNC_BERT` | 0xDF55 | bit error rate test (not decoded) |
| `M17_EOT` | 0x555D | end of transmission |

## 2. Frames (`core/m17/m17_frame.c`, `core/fec/conv.c`, `core/fec/golay.c`)

A frame is held as the framer holds it (`air_frame_t.hard`): 48 bytes of dibits, symbol 0 first. Because M17's
symbols map to dibits as the air interface's do, those bytes are the 16-bit sync and the 368 bits, MSB first.

### 2.1 Coding

Sender's side, for the LSF and the stream frame's FN and payload:

| Step | Bits | What | Spec |
|---|---|---|---|
| Type 1 | 240 (LSF), 144 (FN + payload) | the fields, then 4 zero tail bits | Forward Error Correction |
| Type 2 | 488, 296 | rate 1/2, K = 5 convolutional code: G1 = 1 + D^3 + D^4 (0x19), G2 = 1 + D + D^2 + D^4 (0x17) | C, Convolutional Encoder |
| Type 3 | 368, 272 | punctured: P1 for the LSF (61 entries: a 1, then 1,0,1,1 fifteen times), P2 for the stream (11 ones and a 0) | E, Code Puncturing |
| Type 4 | 368 | quadratic permutation interleaver: bit k is type 3 bit (45k + 92k^2) mod 368 | F, Interleaving |
| On air | 368 | XOR with the randomizer's 46 bytes, behind the sync | B, Randomizer Sequence |

The stream frame's LICH skips the convolutional code: its 48 bits are four Golay(24,12) words (96 bits), placed
before the 272 coded bits. All 368 bits are interleaved and randomized together.

Receiver's side: each payload bit's soft value comes from its symbol (the high bit from the sign, the low bit from the
size), derandomized, deinterleaved and depunctured (0 where a bit was punctured), then Viterbi-decoded (`core/fec/conv`).
Without soft values (`soft` NULL), every bit counts the same. The LICH's Golay words are decoded from hard decisions.

| Function | Returns |
|---|---|
| `m17_lsf_get` | bits corrected, or -1 when the CRC fails |
| `m17_lich_get` | bits the Golay code corrected (0 to 12), or -1 when a word is past its reach |
| `m17_stream_get` | bits corrected. No CRC covers FN and the payload: a large count means noise |

The decoders' memory is the caller's (`m17_fec_work_t`, 976 bytes): no large buffer on a task's stack.

### 2.2 Link setup frame (LSF)

| Bytes | Field | Spec |
|---|---|---|
| 0-5 | DST: the destination address (3), big-endian | Link Setup |
| 6-11 | SRC: the source address | Link Setup |
| 12-13 | TYPE, big-endian (below) | Link Setup |
| 14-27 | META: 14 bytes, by TYPE's subtype | Link Setup |
| 28-29 | CRC over bytes 0-27, big-endian | CRC |

| TYPE bits | Field |
|---|---|
| 0 | 1 stream, 0 packet |
| 1-2 | data type: 10 voice (Codec 2 3200), 11 voice and data (Codec 2 1600) |
| 3-4 | encryption type: 00 none |
| 5-6 | encryption subtype, or the META type without encryption |
| 7-10 | channel access number (CAN) |
| 11 | signed stream |
| 12-15 | reserved |

CRC: polynomial 0x5935, register loaded with 0xFFFF, MSB first, nothing reflected or inverted. Over a block followed
by its CRC it gives 0. Check values: empty 0xFFFF, "A" 0x206E, "123456789" 0x772B, bytes 0x00 to 0xFF 0x1C31.

### 2.3 Stream frame and LICH

| Part | Bits | Content |
|---|---|---|
| LICH | 48 | LSF bytes 5n to 5n+4, then a byte with the counter n (0 to 5) in bits 7-5 |
| FN | 16 | frame number: bit 15 marks the last frame, bits 14-0 count from 0 and wrap |
| Payload | 128 | voice: two Codec 2 3200 frames of 8 bytes (20 ms each) |

The LICH carries the LSF in six chunks, one per frame, so a receiver that missed the LSF has it again within 240 ms
(`m17_lsf_asm_t`). A chunk that disagrees with the one held starts the set over: another station's stream. The set is
done when all six are in and the CRC holds. Counter values 6 and 7 are ignored.

FN 0x7FFB is a signed stream's authentication frame; the four after it carry the signature (TYPE bit 11). They must
not reach the codec.

## 3. Addresses (`core/m17/m17_addr.c`)

The specification's appendix A, Address Encoding. An address is 48 bits. A callsign of up to nine characters is a
base-40 number, the first character the least significant digit.

| Value | Meaning | Text |
|---|---|---|
| 0 | none (not an address) | "" |
| 1 to 40^9 - 1 | a callsign | its characters |
| 40^9 to 40^9 + 40^8 - 1 | a hash address: '#' and up to eight characters | "#ECHO" |
| up to 0xFFFFFFFFFFFE | reserved | "" |
| 0xFFFFFFFFFFFF | broadcast | "@ALL" |

Alphabet, digit 0 to 39: space, A to Z, 0 to 9, '-', '/', '.'.

| Function | Does |
|---|---|
| `m17_addr_encode` | Text to an address. Lower case reads as upper; trailing spaces don't count; a leading '#' gives a hash address; "@ALL" gives broadcast. Refuses another character, more than nine characters (eight after '#') or nothing |
| `m17_addr_decode` | An address to text (`M17_CALL_TEXT` bytes with the NUL): "@ALL", "#..." or the callsign; "" for 0 and the reserved range |
| `m17_addr_dest` | A channel's destination: blank or "ALL" (any case) is broadcast; else as `m17_addr_encode` |

Examples: "AB1CD" is 0x00000009FDD51 (the specification's), "N0CALL" 0x00004B13D106, "W1AW" 0x0000001680B7.

## 4. Voice (`core/m17/m17_voice.c`)

Codec 2 3200 (codec2-fixed-point, `third_party/codec2-fixed-point`, LGPL-2.1): integer only, 160 samples (20 ms at
8 kHz) to 8 bytes and back, the same result on every CPU. A stream frame carries two codec frames.

The design is P25's voice path (`core/p25/p25Voice.h`): no RTOS call, the memory the caller's, single-producer
single-consumer queues between the engine's task and the audio callback.

| Item | Value |
|---|---|
| Memory (`m17_voice_mem_t`) | the encoder and the decoder in one union (a radio transmits or receives), the two queues, the last frame: 4,720 bytes |
| Receive queue | 16 codec frames (320 ms) |
| Priming | 4 codec frames (two stream frames, 80 ms) before playback starts; a call that ends sooner plays at once |
| A late frame | the last frame plays again once, then silence |
| A new call | what is left of the call before is dropped; the decoder starts fresh |
| Transmit queue | 8 codec frames; the engine takes two for each stream frame |

Where the memory comes from on a radio (`radio_m17_voice_mem`, ADR 006 4): what the board's vocoder lends where it
lends, else P25's memory while P25 idles, else a block of its own. That block is free only while no other air mode
runs. Step 1 doesn't connect the voice path to the radio's audio.

## 5. The CPU benchmark

The debug link's RADIO op 45 ([debuglink.md](debuglink.md) 3.8) times the codec on the radio: codec2-fixed-point's
own test signal (300 frames) through the encoder, then the first 64 frames' bits through the decoder, each frame
timed with `hal_micros`. The `m17` view section gives the average and the slowest frame, in microseconds and as a
share of the 20 ms frame. Two hashes check that the radio computed what a host computes:

| Hash | Value | Over |
|---|---|---|
| `M17_BENCH_ENC_HASH` | 0x9959853f | the bits of all 300 frames (codec2-fixed-point's reference) |
| `M17_BENCH_DEC_HASH` | 0x22ef3d78 | the samples decoded from the first 64 frames' bits |

The codec runs in the block M17's voice will use (4), so the timing includes that memory's speed. The block is free
only on an FM channel without a scan: the op refuses otherwise. A task of its own runs it (2,048-byte stack from the
RTOS heap, freed at the end), above the UI, input and host link tasks, pausing a tick between frames.

The gate, per radio (ADR 006 5): encode at most 50 % of the CPU; the receive path (soft modem, framer and decode,
measured in step 2) at most 60 %.
